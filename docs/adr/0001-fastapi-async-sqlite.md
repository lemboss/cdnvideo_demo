# ADR 0001: FastAPI, async SQLite и Alembic

## Статус
Принято

## Контекст
Сервис должен быть отдельным микросервисом с простым локальным запуском, async API и управляемыми миграциями.

Проект является тестовым заданием, поэтому важны быстрый старт, минимальная инфраструктура и простое воспроизведение окружения.

## Решение
Используем FastAPI, SQLAlchemy 2 async, `aiosqlite` и Alembic. SQLite запускается с WAL, foreign keys и busy timeout.

SQLite выбран потому, что он быстрее разворачивается и требует меньше инфраструктуры, чем PostgreSQL. Для тестового задания это снижает стоимость запуска и проверки сервиса.

## Последствия
Решение подходит для компактного сервиса и локального Docker-запуска.

Для хранения большого количества координат, геоиндексов и сложных spatial-запросов лучше подходит PostgreSQL + PostGIS. Такой вариант функциональнее и масштабируемее для геоданных, но дороже по инфраструктуре, эксплуатации и времени разворачивания.

Если нагрузка, объем данных или требования к геозапросам вырастут, репозиторий можно перенести на PostgreSQL/PostGIS без изменения доменного слоя.
