# ADR 0006: Техническое разбиение кода

## Статус
Принято

## Контекст
Сервис небольшой, но уже содержит HTTP API, бизнес-логику, доступ к БД, интеграцию с Яндекс Геокодером, безопасность и наблюдаемость. Нужно разложить код так, чтобы он оставался читаемым и расширяемым без преждевременного усложнения.

## Решение
Сейчас используется техническое разбиение по слоям:

- `app/api` — HTTP-контракты, роутеры, зависимости и error handlers.
- `app/core` — конфигурация, логирование, middleware, безопасность, БД и общая инфраструктура.
- `app/domain` — доменные модели, ошибки, порты и чистая бизнес-логика вроде Haversine.
- `app/services` — application services и orchestration use cases.
- `app/repositories` — реализации доступа к хранилищу.
- `app/integrations` — внешние клиенты, включая Яндекс Геокодер.

Для контроля стиля и качества Python-кода используется Ruff. Его роль и команды описаны отдельно в `ADR 0005`.

## Последствия
Такое разбиение проще для текущего размера сервиса и хорошо подходит для FastAPI-микросервиса. Если доменная область вырастет, можно перейти к feature-based или bounded-context разбиению без изменения публичного API.
